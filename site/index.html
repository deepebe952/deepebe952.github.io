Introduction

In this work, we study whether frontier models can sustain progress on real-world AI infrastructure optimization over long horizons. Existing evaluations often focus on specific components or shorter optimization budgets, leaving sustained optimization across the infrastructure stack underexplored.

To address this gap, we introduce Infrathon, a benchmark of 25 tasks spanning operators, interacting modules, and complete training or serving workflows. Infrathon supports iterative implementation, profiling, and validation under numerical and hardware constraints, with private task-specific tests. We evaluate six models across 150 runs with 12- or 24-hour budgets and a total budget of over 10,000 GPU-hours.

Task Definition

We organize the 25 tasks in Infrathon by application stage (training or inference), then by optimization level according to their editable scope. Operator-level tasks target computational or data-movement primitives; module-level tasks target functional components within fixed workflows, such as training objectives or KV policies; and system-level tasks target training or generation loops, cross-stage pipelines, and serving orchestration. Table 2 details the 10 training and 15 inference tasks.

Each task starts from a workspace W, which supplies initial code or an interface to implement, together with the editable scope. The agent develops candidate solutions using public tests P, comprising visible cases and a public runner for correctness checks and profiling.

The private tests E specify test cases, task-specific checks, the scoring objective and its direction, and permitted feedback. The Judge environment returns private test results without exposing private test cases or scoring code to the agent.

Development and evaluation run under task-specific resources R, specifying hardware allocation and the software runtime. The framework permits a time budget T ∈ (0, ∞], where T = ∞ denotes execution without a preset wall-clock deadline. For the experiments in this paper, we set T = 12 hours for operator-level tasks and T = 24 hours for module- and system-level tasks, including tool execution and feedback waits.

Task Execution

As shown in Figure 1(b), our task execution framework consists of three components: the Work environment, the Controller, and the Judge environment.

In the Work environment, the agent develops and tests candidates using the task workspace W, public tests P, and resources R.

The trusted Controller manages candidate submissions, including task-specific limits and cooldowns. For each submission, it snapshots the files allowed by W and coordinates an integrity check before forwarding the candidate to the Judge environment.

The Judge environment runs the private tests E on candidate snapshots that pass the Controller's integrity check, using the task-specific hardware and runtime specified by R. The result returns to the agent in the Work environment, allowing it to diagnose failures, revise or roll back its implementation, and submit another candidate within the time budget.

A stop hook prompts further work when an agent attempts to finish. Session recovery resumes eligible exits in the same session and workspace. Both mechanisms use the original run deadline.

Experimental Results

Claude Opus 5.5 achieves the best final performance on 17 tasks and GPT-6 Astra on six. We find that model rankings depend on the evaluation horizon: Astra leads overall at 25% of the budget, while Claude leads at 50%. Moreover, 131 of 143 full-budget runs with midpoint scores improve during the second half, showing that shorter evaluations can miss further optimization gains.

We further analyze agent trajectories and identify task violations, unreliable testing, premature completion, and repeated evaluation of unchanged candidates as barriers to continued improvement. Infrathon provides a testbed for developing agents that reliably improve AI infrastructure and for supporting future research on recursive self-improvement.
