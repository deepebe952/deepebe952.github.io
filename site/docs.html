Setup guide

Install the harness, prepare a task, and run an agent.

Requirements

  • Linux x86-64, Docker 24+, and the NVIDIA Container Toolkit.
  • An H100 NVL or H100 SXM host. The example below uses one GPU for Worker and a separate GPU for Judge.
  • uv, git, jq, flock, rsync, patch, curl, and sha256sum.
  • Credentials for your agent’s model provider.

Set Docker’s default runtime to nvidia and check GPU access:

sudo nvidia-ctk runtime configure --runtime=docker --set-as-default
sudo systemctl restart docker
docker info --format '{{.DefaultRuntime}}'
docker run --rm -e NVIDIA_VISIBLE_DEVICES=all \
  nvidia/cuda:12.8.1-base-ubuntu24.04 nvidia-smi -L

Installation

Clone the repository and install the SForge harness and agent runtime:

git clone https://github.com/deepebe952/infrathon.git
cd infrathon
uv sync --frozen --dev --python 3.12
uv pip install --python .venv/bin/python numpy==2.5.2
uv pip install --python .venv/bin/python \
  --index-url https://download.pytorch.org/whl/cpu torch==2.14.1
launch/build-agent-runtime.sh --agent codex
.venv/bin/sforge --help

Harness and agent versions

The harness is the sforge/ code in this repository. To select a version, check out its Git commit or tag and reinstall its locked dependencies:

git fetch origin --tags
# Replace with the commit or tag you want to run.
HARNESS_REF=eb72a9ce8a4067766b0ffaf99ea23659102b617a
git switch --detach "$HARNESS_REF"
uv sync --frozen --dev --python 3.12
uv pip install --python .venv/bin/python numpy==2.5.2
uv pip install --python .venv/bin/python \
  --index-url https://download.pytorch.org/whl/cpu torch==2.14.1
git rev-parse HEAD

The example selects the repository revision used for this guide. After changing revisions, prepare the task images using that checkout’s publication records.

The agent CLI has a separate version. To build and select a Codex runtime, set CODEX_CLI_VERSION to the version you want:

export CODEX_CLI_VERSION=0.159.3
export SFORGE_AGENT_RUNTIME_DIR="$(realpath -m "../agent_runtimes/codex-$CODEX_CLI_VERSION")"
if [ ! -d "$SFORGE_AGENT_RUNTIME_DIR" ]; then
  launch/build-agent-runtime.sh --agent codex --version "$CODEX_CLI_VERSION"
fi
PATH="$SFORGE_AGENT_RUNTIME_DIR/bin:$PATH" "$SFORGE_AGENT_RUNTIME_DIR/bin/codex" --version

Save these two values in launch/mlsysforge.env, or the task’s run.env for Miles. Changing the agent CLI does not require rebuilding task images.

Configuration

cp launch/mlsysforge.env.example launch/mlsysforge.env

Edit launch/mlsysforge.env with your model credentials and local asset paths. For this first run, leave SFORGE_VERSION_STORE_ROOT unset and set SFORGE_VERSION_STORE_OPTIONAL=1 to retain submission archives without a separate candidate-history store.

Configure the submission reviewer in the same file:

SFORGE_LLM_JUDGE_MODE=enforce
SFORGE_LLM_JUDGE_MODEL=MODEL_ID

Load the completed configuration:

set -a

Host CUDA PyTorch for Flux and StreamDiffusionV2

These launchers check GPU peer access on the host. Put a CUDA PyTorch environment first on PATH:

uv venv ~/.venvs/host-torch --python 3.12
uv pip install --python ~/.venvs/host-torch/bin/python \
  --index-url https://download.pytorch.org/whl/cu128 torch==2.8.0
export PATH=~/.venvs/host-torch/bin:$PATH

Models and data

This example uses Dynamic grouped FP8 GEMM, a kernel task. Select the task, fetch its assets, and verify the download:

TASK=standalone-dynamic-grouped-fp8-h100-v3-scratch
TASK_DIR="tasks/latest/$TASK"
"$TASK_DIR/assets/fetch.sh"
.venv/bin/python scripts/infrathon/assets.py check "$TASK"

To use an existing local copy of the release dataset, set INFRATHON_ASSETS_SOURCE before fetching.

Docker images

Each task publishes a Work image and a public Judge image. Select your hardware and read their tags from images/published.json:

export INFRATHON_HARDWARE=h100-94gb-400w
IMAGE_REPOSITORY="$(jq -r '.repository' scripts/infrathon/registry.json)"
PUBLISHED="$TASK_DIR/images/published.json"
WORK_TAG="$(jq -er --arg hw "$INFRATHON_HARDWARE" '.hardware[$hw].work_tag' "$PUBLISHED")"
JUDGE_TAG="$(jq -er --arg hw "$INFRATHON_HARDWARE" '.hardware[$hw].judge_public_tag' "$PUBLISHED")"
docker pull "$IMAGE_REPOSITORY:$WORK_TAG"
docker pull "$IMAGE_REPOSITORY:$JUDGE_TAG"

Use h100-94gb-400w for H100 NVL or h100-80gb-700w for H100 SXM. The image repository comes from scripts/infrathon/registry.json.

Tags follow <hardware>-<task-directory>-<role>-<release>. For this FP8 task, the Work tag is h100-94gb-400w-standalone-dynamic-grouped-fp8-h100-v3-scratch-work-r1; the Judge tag ends in judge-public-r1. The publication file also records each image’s SHA-256 digest.

Prepare images for launch

Run the task helper to pull by the recorded digest, assign local image names, prepare the Judge’s private-data layer, and write the build record:

INFRATHON_PULL=1 bash "$TASK_DIR/scripts/build_images.sh"

For Miles and MInference, use:

scripts/infrathon/pull_images.sh "$TASK"
Build images from source 
bash "$TASK_DIR/scripts/build_images.sh"

Candidate history

Miles and Concurrent serving use a store for candidate versions. With TASK_DIR set to your task, initialize and register it:

Initialize the store
export SFORGE_VERSION_STORE_ROOT="$PWD/../infrathon-version-store"
.venv/bin/python - "$SFORGE_VERSION_STORE_ROOT" "$TASK_DIR" <<'PY'
import json, sys, uuid
from pathlib import Path
from sforge.harness.version_store import VersionStore
root, task = (Path(p).expanduser().resolve() for p in sys.argv[1:])
specs = list((task / "tasks").glob("*.json"))
assert len(specs) == 1, "Expected one task definition"
task_id = json.loads(specs[0].read_text())["task_id"]
root.mkdir(parents=True, exist_ok=True)
marker = root / ".sforge-version-store.json"
if not marker.exists():
    marker.write_text(json.dumps({"schema_version": 1,
        "kind": "sforge-version-store", "store_id": uuid.uuid4().hex}) + "\n")
VersionStore.open(root)
folder = root / "tasks" / task.name
(folder / "runs").mkdir(parents=True, exist_ok=True)
path = folder / "task.json"
record = {"schema_version": 1, "task_directory": task.name, "task_id": task_id}
if path.exists():
    assert json.loads(path.read_text()) == record, "Existing registration differs"
else:
    path.write_text(json.dumps(record) + "\n")
assert VersionStore.open(root).supports_task(task_id)
print("Registered", task_id, "in", root)
PY
.venv/bin/sforge versions --version-store-root "$SFORGE_VERSION_STORE_ROOT" --verify

For Miles, copy the printed absolute path into SFORGE_VERSION_STORE_ROOT in the task’s run.env. For Concurrent serving, keep this variable exported in the launch shell. Register each task once in the same store.

Run a task

Select separate GPUs for Worker and Judge. Replace the GPU indices, model ID, and authentication path:

nvidia-smi -L
WORK_GPU=0 JUDGE_GPU=1 launch/standalone-fp8/run.sh \
  --model MODEL_ID --effort max --hours 12 \
  --legacy-dual-gpu \
  --auth /path/to/auth.json

Submit a candidate

Inside the running Work environment, run the task’s public tests, then submit the current implementation:

sforge-submit --details
sforge-submit --list

See Tasks for task documentation and launch commands.
