Infrathon/Section 3

Infrathon

Task Definition specifies the workspace, tests, resources, and time budget. Task Execution connects Work, Controller, and Judge in a feedback loop with no fixed horizon limit.

3.1

Task Definition

25 tasks: 10 training and 15 inference, across operator, module, and system levels. Each task follows τ = (W, P, E, R, T).

Explore the tasks →
WWorkspace: starting code or an interface to implement, and the files the agent may edit.
PPublic tests: visible cases and a runner for correctness checks and profiling.
EPrivate tests: hidden cases, task checks, the scoring objective and direction, and permitted feedback.
RResources: task-specific hardware allocation and software runtime.
TTime budget: T ∈ (0, ∞]. Experiments use 12 h for operators and 24 h for modules and systems, including tool runs and feedback waits.
3.2

Task Execution

Work environment

The agent edits candidates, profiles, and runs public tests. Permitted judge feedback guides further changes. A stop hook prompts continued work; session recovery resumes eligible exits in the same workspace under the original deadline.

Controller

The controller snapshots allowed files and coordinates an integrity check, verifying cited evidence before rejection. Candidates with Iτ(c) = 1 proceed to the Judge; rejected candidates return rule feedback without a score.

Judge environment

Private tests check correctness, quality, and any memory constraints, then measure task performance. The result Jτ(c) = (s, z, d) returns a score, status, and permitted diagnostics. Validation failures and infrastructure errors have distinct statuses.

4 · Experimental Results

Configurations

One selected main-experiment run per task–model pair: six configurations, 25 tasks, and 150 runs. All use max reasoning effort on NVIDIA H100 NVL GPUs.

Appendix B: Experimental Setup and Analysis. The main experiment allocates 10,560 GPU-hours, including Work, continuously allocated Judge environments, and serving backends. The time-budget ablation adds 36 short runs and 1,008 GPU-hours, reported separately. Astra was evaluated later than most other runs, under different service conditions.
4.1 · Main Results

Rank score

Scores come in TFLOPS, tokens per second, compression ratios and accuracy points per training hour, so they cannot be averaged. Configurations are ranked within each task instead.

Per task, then averaged
RankScorem(G) = 100 / [|G| · (K − 1)] · ∑τ∈G (K − ρτ,m)

ρτ,m ranks configuration m on task τ by its best valid score (1 = best; exact ties share the average rank). G is the selected task group, and K = 6 is the fixed number of configurations. Tasks have equal weight. Scores of 100 and 0 mean first and last on every task, respectively (paper Eq. 5).

Coverage

All 25 tasks count equally. Each run uses its best valid private-test score. All six configurations cover all 25 tasks; a run without a valid scored submission receives zero.

Uncertainty. The 95% intervals resample tasks with replacement: 10,000 resamples for the full suite, 3,000 for filtered subsets.

Flags

Runs that differ from the rest of the cohort. They are ranked as recorded and marked wherever they appear.
