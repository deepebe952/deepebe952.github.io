How these numbers were measured

Where long-horizon agents break down

The paper examines all six configurations through three questions: task compliance, experimental validation, and continued improvement.

01 · Do agents follow task requirements?
Rejected before scoringIntegrity checks return rule feedback when a candidate skips required work.
  • DeepSeek’s Wan2.2 candidate emits log_complete before the required background fsync finishes.
  • Qwen’s OPD candidate reuses stale KV state even after recognizing that it is inconsistent with updated weights.
  • Fast local tests can miss changes to the required computation or state invariants.
02 · Do agents test their optimizations correctly?
Check what actually ranA benchmark result is only useful when code, configuration, and workload match the claim.
  • Qwen’s Mamba-2 sweep reuses a cached plan, so nominally different configurations run the same kernel.
  • Correcting the source constants changes the apparent speedup in the paper’s public-runner experiment.
  • Flash-KMeans testing shows why balanced labels alone do not represent assignment-produced workloads.
03 · Do agents keep improving?
4.8% → 19.9%Repeated-content submission share, first versus second half, across 141 full-budget runs.
  • After completion claims, further code changes produce gains: GLM/SageAttention +24.8%, Claude/GKD +3.1%, and DeepSeek/SD3.5 +14.0%.
  • 377 of 2,941 identifiable submissions revisit earlier content in the same run, spanning 54 runs and 21 tasks.
  • 131 of 143 full-budget runs with a midpoint score still improve later.
