Task Execution

Candidates move from the Work environment through the Controller to the Judge. Feedback returns to Work to guide the next revision.

  1. Work environment

    The model and its tools act together: inspect files, edit code, profile, run public tests, save candidates, and request private evaluation.

    Each action and observation joins the agent-visible history. Tool outputs, local diagnostics, and permitted feedback guide revisions or rollbacks. Private test cases and scoring code remain hidden.

  2. Controller

    The trusted Controller snapshots allowed files and manages submission limits and cooldowns. An agent checks the snapshot against task instructions and editable scope; the Controller verifies the cited evidence before rejecting it.

    Accepted snapshots go to the Judge. An integrity rejection returns a reason and no performance score. Explicit saves and accepted submissions are recorded with timestamps.

  3. Judge environment

    Private tests run on accepted snapshots using the task’s allocated hardware and runtime. Validation can require exact outputs, numerical tolerances, or downstream quality thresholds.

    Performance follows the task objective, such as latency, training throughput, or serving throughput. Memory use is measured when the task imposes a resource constraint.

Feedback closes the loop

The Judge returns a task-specific score, an execution and validation status, and permitted diagnostics. Validation failures and infrastructure errors have distinct statuses. Both private results and integrity-rejection feedback return to Work, where the agent can diagnose, revise, roll back, and submit again.

Score
The task’s performance result.
Status
Execution and validation outcome.
Diagnostics
Feedback permitted by the task specification.

Continued execution

A stop hook prompts further work when the agent attempts to finish. Session recovery resumes eligible exits in the same session and workspace. Both use the original run deadline, so continuation does not reset the time budget.

The interaction loop has no fixed upper horizon in the framework. The reported experiments stop at their 12-hour or 24-hour deadline.
