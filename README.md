# Infrathon website

Static site for **Infrathon: Can Frontier Models Solve Long-Horizon AI Infrastructure Tasks?**
It is plain HTML, CSS and JavaScript with no build framework. Every chart is drawn in the browser from one generated data file.

```
site/                    what gets published
  index.html             leaderboard, task map, results matrix, highlights
  tasks.html             all 25 tasks, filterable
  task.html#<key>        one task: details, final scores, trajectories, run trace
  analysis.html          stage x level, ranking stability, final vs best, trajectories, efficiency, behaviour
  runs.html#<task>/<m>   per-run submission logs and a sortable table of all 150 runs
  method.html            protocol, rank score, configurations, citation
  assets/css/site.css    design tokens and layout
  assets/js/core.js      shared data access, rank math, charts, nav/footer
  assets/js/<page>.js    one script per page
  assets/img/            current paper figures and official institution logos
  data/infrathon.js      GENERATED by scripts/build_data.py
data/
  tasks.json             task registry: names, levels, metrics, flags, ranking eligibility
  tokens.json            visible-output and action totals from paper Figure 7
  raw/runs.json          per-run scores and submissions, extracted from the dashboard export
scripts/
  extract_dashboard.py   dashboard zip -> data/raw/runs.json
  build_data.py          data/* -> site/data/infrathon.js (rank scores, bootstrap, etc.)
  check_site.py          local references, anchors, no leaked local paths
tests/test_data.py       checks the extraction against the paper and the site data
```

## Updating results

```bash
python3 scripts/extract_dashboard.py /path/to/dashboard-tasks-html-YYYYMMDD-HHMMSS.zip
python3 scripts/build_data.py
python3 -m unittest discover -s tests -v
```

`extract_dashboard.py` keeps the latest cohort folder of each task (by the trailing date) and applies the paper's run selection. For Miles OPD, it supplements the latest cohort with Astra's latest earlier run when Astra is absent from the release rerun.
The selection drops Gemini, the voided LLaDA DeepSeek attempt, and Sol's local Mamba-2 rerun.
Flags, exclusions and task text live in `data/tasks.json`.
The current source is `dashboard-latest-results-20261025.zip`: one selected page per task, with Astra OPD already merged and Qwen Concurrent agent-22 restored (best score 154.3333). Its manifest supplies the snapshot date. No personal-export deletion is applied.
If a new export changes the paper's numbers, update the expected values in `tests/test_data.py` along with the paper.

Preview locally with `python3 -m http.server -d site 8000`.

## Ranking

The site ranks each run's best valid score during the run, using the rank-score method of the paper (Eq. 5). On each task, every configuration that ran it is ranked by that score; exact ties share the average rank, and a run that never produced a valid score ranks last. Configuration m earns 100 · (n − rank) / (n − 1), where n is the number of configurations that ran the task, and its rank score is the mean over the tasks it ran (all six configurations now cover 25 tasks).

The leaderboard recomputes the score in the browser for any stage or level filter. The 95% intervals and P(#1) come from bootstrap resampling of tasks.

`tests/paper_table4.json` transcribes the 150 printed best-so-far scores from Table 4 of the October 25 paper. Tests check every task/model score to the printed precision and the task-win totals. A run without a scored submission receives zero, as in the paper. Independent final-artifact evaluations remain in raw records and are not used for the leaderboard.

## Deployment

`.github/workflows/pages.yml` runs on every push and pull request.
It rebuilds the data bundle, fails if the committed bundle is stale, runs the tests and site checks, and then deploys `site/` to GitHub Pages from `main`.

One-time repository settings:

1. The repository must be public, or the account needs a plan that allows Pages on private repositories.
2. Under Settings → Pages → Build and deployment, set Source to **GitHub Actions**.

## Appearance and paper content

The default theme is light. `site/assets/js/theme.js` restores an explicit saved preference before the stylesheet loads; the navigation button switches themes without reloading. Charts and inline diagrams use the same CSS variables.

The homepage lists all 18 authors in paper order, with all eight affiliation numbers and the three project-leader marks. Figures 3, 5, and 11 are extracted from the supplied current PDF. Visible output counts follow the paper's common tokenizer definition, not the older API-usage estimates.
